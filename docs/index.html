Run it yourself

You deposit 100 demo dollars into your own Morpho Vault V2 on a test network, turn the watch on, then play the vault’s curator and schedule a rule change. Your deposit should come back by itself.

7 wallet confirmations. About 0.00004 test ETH on Base Sepolia; the page asks for 0.00012 before it starts, as wallets check each transaction against its highest possible fee. About one minute.

The vault is made for you by Morpho’s own Vault V2 factory, through a maker contract of ours that sets its waiting periods. The maker and the demo dollars are ours; the demo dollars have no value. Reactive fees for this demo are paid from our float.

Today’s run count, the float and any debt are read from both chains when the page’s script runs.

How it works

  1. The vault’s curator schedules a rule change. The vault emits its own Submit event and the waiting period starts.
  2. The reactive contract is subscribed to that vault and to the kinds of change you chose, nothing wider. Reactive delivers the event to it.
  3. It asks for a callback on Base Sepolia. The exit contract accepts it only from Reactive’s callback proxy, and only for our reactive contract.
  4. The exit contract redeems your shares. The receiver is read from its own storage: always the depositor.
  5. The vault pays your wallet. No server ran, and there is no key that can send the funds elsewhere.

What each Reactive feature does here

FeatureWhat it does hereWhat breaks without it
Event subscription with topic filters The trigger: the vault’s address, the Submit topic and the selector of each kind you chose. A server that polls the chain and holds a hot key. With a wildcard filter, any stranger’s contract could bill ours into debt and switch the exit off.
Subscribe and unsubscribe at runtime One topic filter per kind of change you chose on your vault (three for the default watch; a cap increase adds two), subscribed when you turn the watch on. Watches on the same vault share filters by count, so the last one to end unsubscribes. One hard-coded vault, and fees for watches nobody holds.
A timer that runs only while a change is waiting The second mode, “wait for the deadline”: Reactive stores the change and asks for the exit 2 minutes before it can run (this demo’s setting). The deposit stays if the curator cancels first. Built in and switched off on this page; our run #6 on these contracts used it, deposit back 65 s after the change with 115 s of notice left (its record). Only “leave now”. Left on all the time, the timer would spend the float while idle.
Callback through the callback proxy The redeem on the vault’s chain, accepted only from the proxy and only on request of our reactive contract. Nothing moves the deposit. With a weaker check anyone could force an exit; the funds would still go only to their owner.
Blocks about one second apart In run #1 Reactive’s transaction landed within a second of the vault’s event, and the deposit was back 1 s after the event. Every run shows its seconds. The exit would still beat a waiting period of days. It counts when the notice is short, like the 3 minutes of this demo.

What this demo is

  • Test networks only.
  • Each vault is a real Morpho Vault V2, made by Morpho’s own factory through our maker contract. The maker and the demo dollar are ours; the dollar has no value.
  • A maker vault waits 180 seconds before a new adapter, a new allocator, a cap increase or a shorter waiting period can take effect. Vaults that hold real deposits usually wait days.
  • A “leave now” watch does not expire: it ends when it fires or when you turn it off. A timer watch can be ended by anyone one day after it was turned on.
  • A watch is served only while our float on Reactive Lasna is above zero; the page shows the float and any debt live. One vault holds at most three watches at a time: a fourth is refused on Reactive Lasna and stays on in the exit contract’s record until its owner turns it off, and a place frees when one of the three ends. If the vault refuses the redeem, the watch ends without a retry. A version for real use would have each depositor fund their own watch; that is not built.
  • Watches turned on per UTC day: 4 per address, 50 for everyone. The timer mode, not offered on this page, is limited to 8 at a time and 4 new a day.
  • A change with no waiting period leaves no time to exit.

Every limit is in the rule book.

Check every claim in ten minutes

  1. The three records belong together. Open the three links of a run above. In a “leave now” run, Reactive’s transaction names the Base Sepolia transaction as its origin. In a “wait for the deadline” run (our run #6, linked in the timer row above) the origin is the timer tick, and the Base Sepolia hash is a topic of the ExitRequested log. In both, the withdrawal’s WatchEnded log carries the same hash.
  2. The deposit went to its owner. In the withdrawal, the token moves from the vault to the depositor. In NoticeExit.sol the receiver is read from storage, never from the callback.
  3. The vault is a real Morpho Vault V2. On Morpho’s Vault V2 factory (address below), isVaultV2 of the run’s vault (the address its “Change scheduled” transaction was sent to) returns true; the page reads it after your deposit. Our maker sets the waiting periods and switches gates and fees off for good, then hands the vault to its caller as curator and owner: you in the guided run, one of our own keys in our recorded runs, where the depositor is also a key of ours. It is a test vault on a test network: it has no adapter and holds only our demo dollar: MorphoVaultMaker.sol.
  4. A cap increase never reaches Reactive by default. NoticeReactive.sol subscribes one filter per chosen selector. Or schedule a cap increase as the curator in the run above: nothing moves.
  5. The numbers are read live. Your browser asks Morpho’s public API and one public endpoint per chain (a second Base Sepolia endpoint only if the first fails). The network tab shows those hosts and this page’s own files, nothing else.
  6. The contracts refuse what the rule book says. Unit, attack, fuzz and invariant tests and a mutation check run in GitHub Actions: see the repository.
