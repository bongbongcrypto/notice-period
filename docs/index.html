How it works

  1. The vault’s curator schedules a rule change. The vault emits its own Submit event and the waiting period starts.
  2. The reactive contract is subscribed to that vault and to the kinds of change you chose, nothing wider. Reactive delivers the event to it.
  3. It asks for a callback on Base Sepolia. The exit contract accepts it only from Reactive’s callback proxy, and only for our reactive contract.
  4. The exit contract redeems your shares. The receiver is read from its own storage: always the depositor.
  5. The vault pays your wallet. No server ran, and there is no key that can send the funds elsewhere.

What each Reactive feature does here

FeatureWhat it does hereWhat breaks without it
Event subscription with topic filters The trigger: the vault’s address, the Submit topic and the selector of each kind you chose. A server that polls the chain and holds a hot key. With a wildcard filter, any stranger’s contract could bill ours into debt and switch the exit off.
Subscribe and unsubscribe at runtime One subscription per watch, added when you turn it on and removed when it ends. One hard-coded vault, and fees for watches nobody holds.
A timer that runs only while a change is waiting The second mode, “wait for the deadline”: Reactive stores the change and asks for the exit 2 minutes before it can run (this demo’s setting). The deposit stays if the curator cancels first. Run #2 above used it. Only “leave now”. Left on all the time, the timer would spend the float while idle.
Callback through the callback proxy The redeem on the vault’s chain, accepted only from the proxy and only on request of our reactive contract. Nothing moves the deposit. With a weaker check anyone could force an exit; the funds would still go only to their owner.
Blocks about one second apart In run #1 Reactive’s transaction carries the same second as the vault’s event, and the deposit was back 2 s later. Every run shows its seconds. The exit would still beat a waiting period of days. It counts when the notice is short, like the 3 minutes of this demo.

What this demo is

  • Test networks only.
  • The vault and the dollars are ours; the vault copies the events of Morpho Vault V2.
  • A watch lasts one day in this demo.
  • A change with no waiting period leaves no time to exit.

Check every claim in ten minutes

  1. The three records belong together. Open the three links of a run above. In a “leave now” run, Reactive’s transaction names the Base Sepolia transaction as its origin. In a “wait for the deadline” run the origin is the timer tick, and the Base Sepolia hash is a topic of the ExitRequested log. In both, the withdrawal’s WatchEnded log carries the same hash.
  2. The deposit went to its owner. In the withdrawal, the token moves from the vault to the depositor. In NoticeExit.sol the receiver is read from storage, never from the callback.
  3. A cap increase never reaches Reactive by default. NoticeReactive.sol subscribes one filter per chosen selector. Or schedule a cap increase as the curator in the run above: nothing moves.
  4. The numbers are read live. Your browser asks Morpho’s public API and one public endpoint per chain (a second Base Sepolia endpoint only if the first fails). The network tab shows those hosts and this page’s own files, nothing else.
  5. The contracts refuse what the rule book says. Unit, attack, fuzz and invariant tests and a mutation check run on every push that touches the contracts: see the repository.
